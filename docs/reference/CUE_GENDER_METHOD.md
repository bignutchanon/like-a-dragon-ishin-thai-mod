> ต้นทาง: `D:\Projects\lost-judgment-thai\docs\reference\CUE_GENDER_METHOD.md`
> พิสูจน์กับ Lost Judgment แล้ว 29 ส.ค. 2026 — ครอบคลุม 15,602 จาก 15,605 แถวบทพูด (99.98%)
> กับดักข้อ 6 และ 7 มาจากโปรเจกต์ Judgment (29 ส.ค. 2026) — ขอบคุณที่ส่งมาให้
> โปรเจกต์อื่นอ่านไฟล์นี้ได้โดยตรง ห้ามแก้จากโปรเจกต์อื่น — แก้ที่ต้นทางแล้วให้ที่อื่นอ่านตาม

## ปัญหาที่วิธีนี้แก้

ภาษาไทยบังคับให้ต้องรู้เพศผู้พูดตั้งแต่คำแรก (ครับ/ค่ะ · ผม/ฉัน/หนู) ขณะที่ต้นฉบับอังกฤษ
ไม่บอกเพศเลย ถ้าเดาผิดจะเห็นทันทีบนจอและแก้ทีหลังแพงมาก กติกาที่ทุกโปรเจกต์ใช้ร่วมกันคือ
**พิสูจน์ไม่ได้ = แปลกลางเพศ ห้ามเดา** — เอกสารนี้คือวิธีขยาย "สิ่งที่พิสูจน์ได้" ให้กว้างที่สุด

ลำดับความน่าเชื่อถือของหลักฐาน เรียงจากดีที่สุด:

1. **คิวเสียงของบรรทัดนั้นเอง** (เอกสารนี้) — ชี้ขาดรายบรรทัด
2. `sound_voicer.bin` คอลัมน์ `sex` ของตัวละครที่ชื่อตรงกับแถว voicer
3. แฟ้มคดี/คำบรรยายตัวละคร (`evidence.bin`) ที่ใช้ he/she
4. สรรพนามอังกฤษในบทของตัวละครนั้น
5. คำนำหน้าชื่อ (-san/-kun/-chan) — อ่อนที่สุด ใช้เป็นตัวช่วยเท่านั้น

## โครงข้อมูลในไฟล์เกม

ไฟล์ที่เกี่ยวข้อง (อยู่ใน db par ของภาษาที่เป็น carrier):

| ไฟล์ | หน้าที่ |
|---|---|
| `sound_auth.bin` | บทพูดคัตซีนทั้งหมด แยกเป็นตารางย่อยชื่อขึ้นต้นด้วย `speech_list_*` |
| `sound_voicer.bin` | ทะเบียนนักพากย์ — คอลัมน์ `sex` (1 = ชาย · 2 = หญิง · 0 = ไม่ระบุ) และ `voice_type` |
| `talk_talker.bin` | ทะเบียนชื่อผู้พูดที่แสดงบนจอ |

ทุกตาราง `speech_list_*` มีสองส่วน:

- `table` — แถวบทพูด คอลัมน์ที่ใช้: `1` = เลขคิวสากล · `3` = index ของผู้พูด ·
  **`4` และ `13` = ข้อความอังกฤษสองรูปของคิวเดียวกัน** (ฉบับเต็มกับฉบับย่อ/รูปที่ตัดคำ)
- `table.subTable` — แถวคิวเสียง **ชื่อแถวคือชื่อคิว** และคอลัมน์ `0` = เลขคิวสากล

ชื่อคิวมีรูปแบบ `speech_<อะไรก็ได้>_<id ของ voicer>` เช่น

```
speech_ja20130_ikatsui_hangure          -> voicer = ikatsui_hangure
speech_m04_03900_seiren                 -> voicer = seiren
speech_g_m_g01_010_030_sakura_kosuke_frnd -> voicer = sakura_kosuke_frnd
```

## อัลกอริทึม

```
สำหรับทุกตาราง speech_list_* :
    สร้างแผนที่  เลขคิวสากล -> ชื่อคิว   จาก subTable (คอลัมน์ 0 -> ชื่อแถว)
    สำหรับทุกแถวบทพูดใน table :
        ข้อความ = ทุกค่าที่ไม่ว่างในคอลัมน์ 4 และ 13   (เก็บแยกกัน ห้ามต่อสตริง)
        ชื่อคิว = แผนที่[ คอลัมน์ 1 ]
        voicer  = ตัดคำหน้าของชื่อคิวทีละท่อนด้วย "_" จนได้ชื่อที่มีจริงใน sound_voicer
        เพศ     = sound_voicer[voicer].sex
        บันทึก  ข้อความ -> เพศ   (นับคะแนนสะสม เผื่อข้อความซ้ำหลายคิว)

สรุปผลต่อข้อความ:
    ชาย > 0 และ หญิง = 0  -> male
    หญิง > 0 และ ชาย = 0  -> female
    มีทั้งสองฝั่ง          -> mixed  (บรรทัดนี้ถูกใช้ซ้ำโดยคนละเพศ = ต้องแปลกลางเพศ)
```

การ "ตัดคำหน้าทีละท่อน" จำเป็นเพราะชื่อคิวมีคำนำหน้าไม่คงที่ (ชื่อฉาก เลขบท เลขคิว)
แต่ id ของ voicer อยู่ท้ายเสมอ วิธีนี้จับได้ทั้ง `seiren` และ `sakura_kosuke_frnd`
โดยไม่ต้องรู้รูปแบบคำนำหน้าล่วงหน้า

## กับดักที่จ่ายค่าเรียนมาแล้ว

1. **อย่าสรุปเพศต่อ "ชื่อผู้พูด" ด้วยเสียงข้างมาก** — เกมใช้ชื่อเดียวกับตัวละครหลายคนได้
   Lost Judgment มี `Sakura` ที่เป็นทั้งนักเรียนชายและเพื่อนหญิง (คิวเสียงชาย 33 : หญิง 9)
   การนับเสียงข้างมากทำให้ 10 บรรทัดของตัวละครหญิงถูกแปลด้วย "ครับ/ผม" แล้วผู้เล่นเห็นบนจอ
   → ต้องเก็บผลแบบ **รายบรรทัด** ไม่ยุบเป็นค่าเดียวต่อชื่อ

2. **คอลัมน์ 4 กับ 13 เป็นข้อความคนละอัน ไม่ใช่ช่องเดียวที่ต้องต่อกัน** — ถ้าต่อสตริง
   จะได้คีย์ที่ไม่มีอยู่จริงในเกม แล้วหาไม่เจอตอนเอาไปจับคู่กับคิวแปล
   (ผลต่างชัดมาก: ต่อสตริง = ชี้ขาดได้ 15,026 คีย์ · แยกเก็บ = 23,562 คีย์)

3. **`mixed` ไม่ใช่ "ไม่รู้" แต่คือ "รู้แน่ว่าใช้ร่วมกันหลายเพศ"** — เป็นหลักฐานเชิงบวก
   ว่าบรรทัดนั้นต้องกลางเพศ ต่างจากบรรทัดที่ไม่มีคิวเสียงเลยซึ่งแค่ "ไม่มีข้อมูล"

4. **บทที่ไม่มีเสียงพากย์ (เช่น `talk.bin` บทเดินเมือง) จะไม่มีคิว** วิธีนี้ช่วยไม่ได้
   ต้องถอยไปใช้หลักฐานชั้นรองหรือแปลกลางเพศ

5. **`voice_type` ใช้เลือกทะเบียนภาษาได้ แต่ห้ามใช้ตัดสินเพศ** — คำญี่ปุ่นบอกทั้งเพศ ช่วงอายุ
   และบุคลิก (`男性_チンピラ_強い` = ชายอันธพาลแข็งกร้าว · `女性_若者_普通` = หญิงสาววัยรุ่นทั่วไป)
   มีค่ามากสำหรับเลือกสำนวน แต่ **ข้อมูลช่องนี้ผิดได้** — Lost Judgment มีสี่แถวที่ `voice_type`
   ขึ้นต้น `男性` ทั้งที่ `sex` = หญิงและเนื้อหาบทเป็นหญิงชัดเจน (`keiko` · `rabuho` ·
   `staff_hat` · `friends_dress` — เช่น keiko พูดว่า "Kosuke-kun... He's a sweet guy, really!")

6. **`sex` บางแถวเป็นเพศของ "นักพากย์" ไม่ใช่ของตัวละคร** — พบครั้งแรกในโปรเจกต์ Judgment:
   `sumire` เป็นโฮสเตสหญิงแต่ `sex` = ชาย · `kjart_woman` = ชาย · `alpes_boy` เป็นเด็กเสิร์ฟชาย
   แต่ `sex` = หญิง (ผู้หญิงพากย์เสียงเด็กผู้ชาย ซึ่งเป็นเรื่องปกติมากในวงการพากย์ญี่ปุ่น)
   ตัวละครหลักตรงหมด พลาดเฉพาะ NPC

   **กติกา: เมื่อคอลัมน์ `sex` ขัดกับทะเบียนตัวละคร ให้ทะเบียนตัวละครชนะเสมอ**
   แล้วใส่ id ของ voicer นั้นลง `SKIP_VOICERS` ใน `make_line_gender.py` **พร้อมเหตุผทุกครั้ง**
   (Lost Judgment ตรวจแล้วเมื่อ 29 ส.ค. 2026 ยังไม่พบแถวแบบนี้ — `SKIP_VOICERS` จึงว่างอยู่)

7. **คิวเสียงขัดกับผู้พูดใน `talk.bin` = บรรทัดถูกใช้ร่วมกันสองเพศจริง ต้องแปลกลางเพศ**
   พบครั้งแรกในโปรเจกต์ Judgment จากบรรทัด `"Good luck."` ซึ่งเป็นได้ทั้งมาฟุยุและยากามิ
   เกมใช้บรรทัดสั้น ๆ ซ้ำข้ามตัวละครเป็นเรื่องปกติ ถ้าเชื่อคิวเสียงฝ่ายเดียวจะได้เพศผิดครึ่งหนึ่งเสมอ

   วิธีตรวจ: เอาข้อความที่ชี้ขาดจากคิวเสียงไปเทียบกับผู้พูดของข้อความเดียวกันใน `talk.bin`
   (ผ่าน `talk_talker.bin` แล้วดูเพศจากทะเบียนตัวละคร) ถ้าไม่ตรงให้บังคับเป็น `mixed`
   `make_line_gender.py` ทำขั้นตอนนี้ให้แล้วในฟังก์ชัน `cross_source_conflicts()`
   และใส่ฟิลด์ `cross_source` ไว้ในผลลัพธ์เพื่อให้ตามรอยได้

   Lost Judgment เจอ **83 ข้อความไม่ซ้ำ / 114 คู่ที่ขัดกัน** (เช่น `"Thank you very much."` ·
   `"Um..."` · `"Hello."` · `"Yeah..."`) ทั้งหมดบังเอิญแปลกลางเพศอยู่แล้วเพราะเป็นวลีสั้น
   แต่ในภาคอื่นอาจไม่โชคดีแบบนี้ — ต้องตรวจทุกครั้ง

## สคริปต์อ้างอิง

อยู่ใน `D:\Projects\lost-judgment-thai\scripts\` — พอร์ตไปโปรเจกต์อื่นได้โดยแก้แค่ path ใน `paths.py`

| สคริปต์ | ผลลัพธ์ | ใช้เมื่อไร |
|---|---|---|
| `make_cue_gender.py` | `extracted/facts/cue_gender.json` — สรุป **ต่อชื่อผู้พูด** | ทำทะเบียนตัวละคร (`characters_*.json`) |
| `make_line_gender.py` | `extracted/facts/line_gender.json` — สรุป **ต่อบรรทัด** | ตั้งธงเพศในไฟล์บริบทของแต่ละ batch และตรวจย้อนหลัง |

รูปผลลัพธ์ของ `line_gender.json`:

```json
{
 "I probably wouldn't have seen you today either\nif I hadn't mistaken you for someone else.": {
  "gender": "female",
  "votes": {"male": 0, "female": 1},
  "example_cue": "speech_g_m_g01_010_030_sakura_kosuke_frnd",
  "speakers": ["Sakura"],
  "voice_types": ["女性_若者_普通"]
 }
}
```

## วิธีใช้กับคิวแปล

1. รัน `make_line_gender.py --write` หลัง extract db เสร็จ
2. ตอนสร้างไฟล์บริบทของแต่ละ batch ให้ค้น `line_gender.json` ด้วย **ข้อความ EN ตรงเป๊ะ** ก่อน
   ถ้าเจอและไม่ใช่ `mixed` → ตั้งธงเพศจากตรงนี้ พร้อม `neutral: false`
3. ถ้าไม่เจอ หรือได้ `mixed` → ถอยไปใช้หลักฐานชั้นรอง และถ้ายังไม่ชัด → `neutral: true`
4. **ห้ามตั้ง `neutral: false` เมื่อหลักฐานระดับตัวละครขัดกันเอง** (`medium-conflict`)
   ไม่ว่าเสียงข้างมากจะเอนไปทางไหน
